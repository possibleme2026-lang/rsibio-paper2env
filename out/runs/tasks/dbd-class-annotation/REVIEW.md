# Review notes

- Data substitution: the paper's DNABERT-based 23-class DBD classifier cannot be trained or shipped deterministically, so the task targets the statistically calibrated, competition-aware DBD-class assignment problem the paper formalises. All inputs are synthetic-but-realistic: 23 class-level PPMs (width 15-19, ~1.2-1.9 bits/column), a human-like background (A/T 0.295, C/G 0.205), 520 test sequences of 120 bp (62 KB FASTA) plus a 200-sequence labelled calibration set, generated at image-build time by environment/data/gen_inputs.py.
- Shortcut probe considered: (a) re-reading the data generator to recover embedded motif classes/positions - the generator runs only in a builder stage, so the final image contains only the generated files; (b) editing /app/data/test_sequences.fa to match predictions - the grader regenerates the whole dataset from tests/gold_gen.py and uses its own copy as ground truth, and reports an input-integrity flag; (c) Monte-Carlo p-values - these are checked against the exact dynamic-programming tail probability of the discretised score; (d) only calibrating on the labelled calibration set - the thresholds and tie-break rules are fully specified, so calibration alone cannot produce the required score/p-value columns.
- Tool chain: python:3.11-slim with numpy/biopython plus real domain binaries (EMBOSS, bedtools, samtools) so the agent has genuine sequence tooling; the graded ground truth is the exact generative + reference process reconstructed inside tests/gold_gen.py (no external binary is authoritative for this synthetic model).
- Ground truth definition: a sequence's true label is the DBD class of its single deliberately planted functional site (or None for background-only sequences). Weaker competing sites are also planted, so the truth is recoverable but not trivially so, and macro-F1 has a realistic ceiling well below 1.0; the grader also prints the reference pipeline's own macro-F1 as a calibration aid.
- Known limitations: class names approximate real TFClass level-2 families but the PPMs are synthetic; the reference implementation in tests/gold_gen.py must stay byte-identical to environment/data/gen_inputs.py (same seeds 20241220/771103/550219) or the integrity flag and macro-F1 check will degrade - both files carry the identical generation core.
- Grading: nine independently weighted checks, partial credit per check; reward.json contains only {'score': float, 'reward': float}, the per-check breakdown is printed to stdout and written to /logs/verifier/report.json.
