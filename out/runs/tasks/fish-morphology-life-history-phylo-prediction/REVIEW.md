# Review notes

- Data substitution: the real DEB-IPM life-history axes, photographs and molecular phylogeny are not redistributable here, so a deterministic synthetic-but-realistic dataset is generated (seed 20251112): a coalescent ultrametric tree of 288 tips, 290 species x 8 lateral-view morphological traits with realistic ranges (body elongation 0.7-4.5, relative eye size 0.07-0.35, gape angle -30..55 deg, plus fin/mouth/head ratios), 12 randomly missing trait cells, and two life-history axes generated exactly as the paper's finding describes - generation turnover depends on lateral-size morphology with water-column-position interactions, reproductive output depends on lateral-size morphology with clade interactions - plus phylogenetically structured and independent residuals.
- Build-time generation: environment/data/generate_data.py is the same file as tests/gold_gen.py (one source of truth). It is executed in a disposable Docker build stage (FROM python:3.11-slim AS data-builder) that writes /build/generated, and only the generated CSV/NWK/TXT files are copied into /app/data of the final image. The generator is therefore inside the task image's build context but never inside the final image or the agent's filesystem, so the hidden held-out life histories cannot be recovered by the agent. The final image contains only morphology.csv (290 rows), life_history_train.csv (238 rows), phylogeny.nwk (288 tips, ~40 KB Newick), test_species.txt (50 names).
- Shortcut probes considered: (1) reading the generator from the image - not possible, multi-stage build discards it; (2) skipping phylogenetic correction and using plain PCA/OLS - the PC1 variance-explained + 8 loading checks and the 3 PGLS slope checks are recomputed by the grader from the tree covariance and will not match un-corrected values; (3) hard-coding diagnostics - the reference values are recomputed from the protected seed at verify time and are not present anywhere the agent can read; (4) predicting a constant - the accuracy components use correlations, so constants score 0; (5) predicting the training-set mean or guessing the paper's regression coefficients - correlation with the withheld values is required.
- Tool chain: numpy/pandas/scipy/scikit-learn for the modelling, Biopython and DendroPy for Newick parsing and tree handling, statsmodels available for GLS. No R dependency is required, but the task is solvable with any of these libraries; the grader recomputes the reference with plain numpy so there is no dependency on a specific package's PCA conventions.
- Determinism: numpy is pinned to 1.26.4 in BOTH the builder stage and the final image, and the generator uses a single np.random.default_rng(seed) stream, so the build-time inputs and the verifier-time gold are bit-identical. Whitening convention: the instruction fixes the symmetric inverse square root C^{-1/2}; PCA scores/eigenvalues differ only at finite-sample O(1/sqrt(n)) level between the symmetric and Cholesky whitening conventions, which is inside the grader tolerances (loadings +/-0.20, variance explained +/-0.06).
- Known limitations: accuracy thresholds (full credit at r>=0.72 for generation turnover and r>=0.65 for reproductive output) were chosen so that a well-specified interaction model reaches full credit while a main-effects-only model only earns partial credit; the actual attainable r was estimated analytically from the signal-to-noise ratio built into the generator, not measured, because the generator cannot be executed in this authoring environment. The PGLS reference used by the grader standardises traits on the 238 training species exactly as the instruction states, so a solution that z-scores on all 288 species would lose part of the slope component; this is stated explicitly in the instruction.
