# Review notes

- Data substitution: no real C. elegans data are available for this preprint, so all inputs are generated by a deterministic synthetic model (seed 20260529, tests/gold_gen.py). Sizes and formats are realistic (800 genes x 16 bulk time points; 1500/1800 cells x 800 genes single-cell atlases with dropout; 72 experimental positives, 120 experimental negatives, 132 low-confidence annotations of which only 24 are truly OXPHOS, 476 unlabelled genes). Gene identifiers follow the WBGene format but gene names are synthetic (ceg-XXXX) so the answer cannot be looked up in an external database.
- Shortcut probes considered: (i) reading the generator script - the image builds /app/data with gen_inputs.py and deletes it in the same build step, so only the observable tables remain in the container, and the hidden label vector exists only in the verifier phase; (ii) simply ranking all low-confidence-annotated genes above the unlabelled genes, which yields AUROC approx 0.64 (below the 0.86 full-credit target); (iii) single-modality baselines: 45% of true positives carry only a bulk temporal signature and 45% only a single-cell co-expression signature, with module-specific decoys planted in each modality, so bulk-only and co-expression-only approaches both cap near AUROC 0.75 while a genuine two-stream integration reaches approx 0.88-0.92; (iv) atlas-specific decoy genes mean that using one single-cell atlas alone leaves roughly 30 spurious high-ranked genes.
- Tool chain: canonical Python scientific stack (numpy, pandas, scipy, scikit-learn) installed in the image; no external domain binary is ground truth for this machine-learning task. The reference solution uses logistic-regression temporal classifiers with leave-one-complex-out bagging plus Pearson co-expression against the high-confidence set in both atlases.
- Invariant/open information: n_round1_positives must equal the 72 rows of high_confidence_oxphos.tsv, n_module_models must be 5, and per_module_auroc must use exactly the complex names present in the annotation file; these are checked without revealing the held-out labels.
- Known limitations: per-module AUROC values in report.json are self-reported by the agent and only range-checked (they cannot be independently recomputed without dictating the model); the two-round pseudo-labelling threshold is intentionally left to the agent, only the count range is enforced. Signal strengths were tuned by design rather than by fitting to real data, so the AUROC ramps (0.62-0.86 overall, 0.55-0.75 on the low-confidence subset) are deliberately generous to absorb implementation variance.
