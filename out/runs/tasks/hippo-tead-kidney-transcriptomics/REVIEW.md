# Review notes

- Data substitution: the paper's in vivo kidney RNA-seq is not public; the task ships 2,000 genes x 30 samples of synthetic negative-binomial counts (5 conditions x 6 replicates: vehicle, TEADi 3 mg/kg, TEADi 30 mg/kg, TEADi 30 mg/kg + 14 d washout, tamoxifen-induced YAP/TAZ KD) generated deterministically at image build time by environment/data/gen_inputs.py (seed 20260801). The generator is deleted from the image after the data are written, and tests/gold_gen.py holds the verifier copy so the ground truth is always recomputed rather than trusted.
- Tool chain: ground truth is PyDESeq2 (pydeseq2 0.4.x) with design '~condition', DeseqStats(contrast=[...], independent_filter=False) and no LFC shrinkage; the grader calls the identical API, so numeric agreement forces the agent to use the canonical tool rather than a hand-rolled t-test.
- Shortcut probes considered: (a) reading a hidden answer file - impossible, gold is recomputed in tests/ from the seed and no answer file exists in the image; (b) editing /app/data to make the statistics trivial - the grader regenerates the matrix from its own seed copy and never reads the agent-visible CSVs; (c) reverse-engineering the generator's per-gene effect sizes - the generator is removed from the image, and the sampled log2FoldChange estimates differ from the planted true effects by ~0.25 (well outside the 0.10 panel tolerance); (d) guessing the constraint values - ten independent numeric checks with tight tolerances.
- Interface risk accepted: the permutation p-value is specified with numpy.random.default_rng(42) and 1,000 draws; because the aldosterone panel is strongly suppressed the observed statistic is far outside every null draw, so the gold value is the floor 1/1001 and is robust to small implementation differences.
- Known limitations: the synthetic effect programme is designed (not measured), so absolute DE counts are illustrative rather than reproducing the paper's exact numbers; histopathology endpoints of the paper are not modelled. Docker pins pydeseq2 to the 0.4.x series because solver and verifier share the container and therefore the same version.
