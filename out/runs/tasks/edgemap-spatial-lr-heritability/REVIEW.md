# Review notes

- Data substitution: the real Visium/Visium-HD sections, 1000G LD reference and GWAS summary statistics are replaced by a deterministic simulator (environment/data/gen_inputs.py, seed 20260329) that preserves the shapes and semantics of the originals: 5 tissues x 900 spots x 200 genes of raw UMI counts on a 30x30 grid, 90 ligand-receptor pairs, 800 SNP loci with block LD, and 6 traits x 800 GWAS z-scores. Data are generated at image-build time and the generator is deleted afterwards.
- Shortcut probe: (i) the generator that encodes the simulation seed and the causal gene structure is removed from the image, so the top-10 prioritised genes are never present on the agent-visible filesystem; (ii) reading gwas_sumstats.tsv alone does not reveal which annotation drives the signal -- the signal is only recoverable by actually running the LD-score regression; (iii) the grader ignores /app/data entirely and re-derives the gold standard from a freshly regenerated copy of the inputs, so tampering with the inputs cannot make the checks pass.
- Tool chain: python:3.11-slim with numpy, pandas, scipy and statsmodels (statsmodels.OLS reproduces the specified classical standard errors). No domain binary is needed because the ground-truth computation is a linear-regression / spatial-statistic pipeline that must be implemented by the agent.
- Known limitations: GWAS data are simulated from an LD-score model, so the tissue-matched effect sizes are illustrative rather than calibrated to the paper; the matched-vs-unmatched contrast is therefore graded as a per-trait pattern match with partial credit instead of a single binary test. Moran's I is used as the explicit spatial statistic because the exact definition must be reproducible by an outside implementation; in the source paper the spatial weighting of LR contexts is estimated, not fixed.
- Grading: score = 0.10 * format + 0.30 * edge_z accuracy + 0.15 * conditional (intrinsic_z/delta_z) + 0.15 * tissue pattern + 0.15 * per-gene z/edge_score + 0.15 * F1 of the prioritised set. reward.json contains only {'score': float, 'reward': float}; the per-constraint breakdown is written to /logs/verifier/report.json and stdout.
